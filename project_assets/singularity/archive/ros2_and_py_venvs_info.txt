    You can combine ROS 2 nodes and Python code that relies on virtual environments. When running Python code that interacts with ROS 2, you should:
        Activate the virtual environment first (if needed).
        Source the ROS 2 setup script.
        Run your ROS 2 Python node (e.g., ros2 run <package> <node>).
        ROS 2 will use the system-wide Python by default unless specified otherwise.

To automatically launch different ROS 2 nodes with different virtual environment dependencies using a ROS 2 **launch file**, you need to ensure that:

1. **The correct virtual environment is activated for each node** before it is executed.
2. **ROS 2 environment is sourced** in the launch file to ensure that ROS 2 commands work as expected.
3. **Launch file handles node execution in the proper environment**, especially when dealing with Python-based ROS 2 nodes that require specific dependencies installed in virtual environments.

### General Approach

You will likely need to use **Python launch files** (`.py` files) instead of **XML-based launch files** to have more flexibility in handling virtual environment activation.

### Steps to Achieve This:

1. **Activate the virtual environment in the launch file**: You can set up a **Python virtual environment activation** inside your launch file by using the `subprocess` module or a shell script, to activate the virtual environment for each specific node before launching it.

2. **Use `LaunchDescription` in the launch file**: A Python launch file in ROS 2 allows you to define a `LaunchDescription`, which will launch the required nodes. Within this, you can define a script to activate the virtual environment and then launch the ROS 2 nodes.

### Example Setup

Let’s assume you have two ROS 2 nodes:
- **Node 1** depends on `acados`, which is installed in the virtual environment located at `$HOME/acados-env`.
- **Node 2** depends on `gym-pybullet-drones`, which is installed in the virtual environment located at `$HOME/gym-pybullet-drones-env`.

You want to launch both nodes with their respective virtual environments.

### 1. **Create a Python Launch File**:

Here’s an example of how you can write a Python launch file (`launch_file.py`) that launches two nodes with different virtual environment dependencies.

```python
import os
import sys
import subprocess
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, LogInfo, ExecuteProcess
from launch_ros.actions import Node

def launch_node_with_virtualenv(env_name, node_name, package_name):
    """
    Helper function to launch a ROS 2 node with a specific virtual environment activated.
    
    :param env_name: The name of the virtual environment directory
    :param node_name: The name of the ROS 2 node to launch
    :param package_name: The ROS 2 package where the node is located
    """
    # Create the command to activate the virtual environment and run the node
    activate_env = f"source {env_name}/bin/activate && "
    run_node_cmd = f"ros2 run {package_name} {node_name}"

    # Combine them to form the full shell command
    full_cmd = activate_env + run_node_cmd

    # Return the ExecuteProcess action to launch the node
    return ExecuteProcess(
        cmd=[full_cmd],
        shell=True,
        output='screen'
    )

def generate_launch_description():
    """
    Launch description for launching ROS 2 nodes with specific virtual environments.
    """

    # Node 1 (acados-related node)
    node1_virtualenv = os.path.expanduser('$HOME/acados-env')  # Path to acados virtualenv
    node1_package_name = 'acados_package'  # Replace with your actual ROS 2 package name
    node1_name = 'acados_node'  # Replace with your actual node name
    
    # Node 2 (gym-pybullet-drones-related node)
    node2_virtualenv = os.path.expanduser('$HOME/gym-pybullet-drones-env')  # Path to gym-pybullet-drones virtualenv
    node2_package_name = 'gym_pybullet_drones_package'  # Replace with your actual ROS 2 package name
    node2_name = 'gym_pybullet_drones_node'  # Replace with your actual node name

    return LaunchDescription([
        # Launch Node 1 (acados-related node) with the appropriate virtual environment
        launch_node_with_virtualenv(node1_virtualenv, node1_name, node1_package_name),
        
        # Launch Node 2 (gym-pybullet-drones-related node) with the appropriate virtual environment
        launch_node_with_virtualenv(node2_virtualenv, node2_name, node2_package_name),
    ])
```

### Key Points in This Launch File:
- **Activate the Virtual Environment**: For each node, we define a shell command that sources the specific virtual environment using `source <env_name>/bin/activate`. After that, we run the ROS 2 node using `ros2 run <package_name> <node_name>`.
- **Use `ExecuteProcess`**: This ROS 2 action runs the specified command (i.e., activating the virtual environment and running the node) in a separate process.
- **Path Expansion with `os.path.expanduser`**: This ensures that `$HOME` is correctly expanded to the user's home directory.

### 2. **Launch the File**:

You can launch this file from the command line as follows:

```bash
ros2 launch <your_package_name> launch_file.py
```

This will launch both nodes, ensuring that each node is executed with its respective virtual environment.

### 3. **Alternative Approach: Using Shell Scripts (Less Preferred)**:

Alternatively, you can use shell scripts to activate the virtual environments before running the nodes, but using Python-based launch files is more flexible and integrated with ROS 2's `launch` system.

If you want to use shell scripts, you would have to use `ExecuteProcess` in your launch file to call a shell script, which activates the environment and runs the node.

For example, the shell script (`launch_with_env.sh`) could look like this:

```bash
#!/bin/bash
# Activate the correct virtual environment
source $HOME/acados-env/bin/activate
# Run the ROS 2 node
ros2 run acados_package acados_node
```

In the Python launch file, you would use `ExecuteProcess` to execute this script.

### 4. **Handling ROS 2 and Python Nodes with Dependencies**:

When you're working with **Python-based ROS 2 nodes** and different virtual environments, the following process should be followed:

- Always **source ROS 2 setup files** first: `source /opt/ros/humble/setup.bash`.
- Then **activate the corresponding virtual environment** for each node using the appropriate `source $HOME/<env_name>/bin/activate` command before running the node.
- Using **Python-based launch files** gives you flexibility to handle virtual environment setup and ROS 2 node execution in one seamless process.

### Conclusion:
By using a Python launch file, you can easily handle launching different ROS 2 nodes, each with its own virtual environment and set of dependencies. The key is to activate the appropriate virtual environment for each node before running it, which can be done directly within the launch file using shell commands or scripts. This way, you don't need to worry about manually activating the environments each time, and everything can be automated within the ROS 2 launch framework.
